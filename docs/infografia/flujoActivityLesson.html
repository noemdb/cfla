Modelo: Pevaluacion

1. Asignación de Carga

Planificación crea la carga académica (modelo Pevaluacion), el ancla que vincula: Profesor + Sección + Asignatura + Lapso. El profesor no puede crearla.

Modelo: Activity

2. Registro de Actividad

El profesor define tema, descripción y estructura (Inicio, Desarrollo, Cierre). Nace con status = false (En revisión).

GATE 1

3. Aprobación Académica

Planificación cambia a status = true. Sin esto, la actividad es invisible para el estudiante, sin importar el estado LMS.

4. Montaje del Contenido

El profesor agrega secciones, textos, videos y recursos. Cada elemento tiene su propio interruptor:

LmsActivityPublication

5. Programación y Publicación

Se define publish_at (y opcionalmente unpublish_at). El sistema lo compara con now(): si es futura queda SCHEDULED y se activa sola cuando llega el momento (cron lms:publish-scheduled cada 5 min).

StudentScopeService

6. Scoping y Consumo

El sistema valida que la seccion_id coincida con la inscripción del estudiante. Si pasa, accede al Dashboard, consume y genera logs (VIEW, COMPLETE).

Expiración

7. Expiración / Archivo

Al llegar unpublish_at o por acción manual (ARCHIVED), desaparece de los listados. Enlaces directos retornan 404.

Los 6 Candados de Visibilidad

Para que un estudiante vea una lección, TODAS estas condiciones deben ser verdaderas simultáneamente.

1

Aprobación

Activity.status == true
2

Contenido Visible

A nivel de contenido: secciones, contenidos y recursos se filtran con is_visible == true

3

Estado Activo

status IN ('PUBLISHED', 'SCHEDULED')
4

Fecha Válida

publish_at no es nulo. Define si es Vista Previa o Completa.

5

No Expirada

unpublish_at >= now() OR null
6

Scoping de Sección

Pevaluacion.seccion_id coincide con la inscripción del estudiante.
